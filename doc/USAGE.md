# 使用统计

安装第三方包 [Keyfreq](https://github.com/dacap/keyfreq) 后，重启 Emacs 即开始
记录命令调用次数。正常交互启动会启用 `keyfreq-mode` 和 `keyfreq-autosave-mode`；
批处理测试和批处理包维护不启用采集，也不启动保存定时器。

## 查看与保存

入口见[快捷键](KEYBINDINGS.md)。也可以直接运行：

- `M-x my/usage-show`：查看所有模式的累计排行。
- `M-x my/usage-snapshot`：导出带 UTC 时间的 JSON 快照，路径显示在消息区。

查看当前 major mode 统计的按键也列在[快捷键](KEYBINDINGS.md)中。
报告中的快捷键来自当前绑定查询，不代表当时实际使用的键位。

Keyfreq 默认每 600 秒保存一次累计计数，正常退出 Emacs 时也会保存。
快照同时包含已经保存的计数和本次会话未保存的增量；导出不会清零或重复累计。
异常退出可能丢失最近一次自动保存后的计数。

## 每周回顾

开始使用时导出一次快照，之后每周手动导出一次。每次导出都生成新文件。
快照是累计值；比较相邻两份中同一模式、同一命令的差值，才是该时间段的使用次数。
如果中途清空统计，应重新留一份基线，不能直接与清空前相减。

自然使用两周后，可让助手读取快照和当前配置，一起看：

- 哪些功能经常使用，调用是否顺手。
- 新增功能是否逐渐进入日常习惯。
- 移动、搜索和标题跳转之间是否有值得尝试的改进。

普通文字输入命令 `self-insert-command` 和 `org-self-insert-command` 不计入排行。
移动命令保留，可在分析时单独归组。低频功能可能仍然很重要，命令次数也不是使用时长
或效率评分。切换模式、minibuffer 和 Evil 操作的归属受 Keyfreq 采集方式影响，
统计只作为使用习惯的线索。

第一阶段统计命令和模式，不区分同一命令的不同快捷键，也不单独跟踪交互命令内部
调用的每个函数。实际按键入口分析留待有需要时再扩展。

## 本地数据

所有文件都位于 `~/.emacs.d/usage/`，已被 Git 忽略：

```text
usage/keyfreq                  累计计数
usage/keyfreq.lock             Keyfreq 保存时的临时锁
usage/snapshots/*.json         带日期的累计快照
```

数据目录仅当前用户可访问，快照权限为 `0600`。保存内容是模式名、命令名和次数；
快照另含导出时间和格式版本，不保存正文、搜索词、文件名或原始按键序列。
采集不需要联网，也不会自动上传或修改配置。

快照使用直接可读的 `counts` 数组，每项包含 `mode`、`command` 和 `count`。
空统计也可以导出，便于保留起始基线。
重新安装配置不会带回这些本地数据；若要换机后继续比较，需要另行保留累计文件和快照。

## 暂停

运行 `M-x keyfreq-mode` 可暂停／恢复采集。自动保存仍可保存暂停前的计数。
重启 Emacs 后按配置重新启用；`M-x keyfreq-reset` 会清空累计统计并要求确认，
已有 JSON 快照保留。
